How it works

1. Batches list is loaded from a static /allbatches.json file (served by the Next.js app, gated by Cloudflare Turnstile cookies).

2. Batch details, subjects, topics, content are fetched from apiserver.deltastudy.site/api/pw/*, which proxies the real Physics Wallah API at api.penpencil.co.

3. Most proxy responses are AES-256-GCM encrypted — the server returns a hex string iv:ciphertext; the client decrypts with a hardcoded key before use.

4. Live classes (/api/pw/live) are returned in plaintext (not encrypted).

3 Authentication Flow

The site uses Cloudflare Turnstile for bot protection and an OTP-based phone login for access.

Turnstile Verify

POST /api/turnstile/verify

Same-origin Next.js route. Verifies the Cloudflare Turnstile token and sets a session cookie that gates /allbatches.json.

Phone Login

POST {API_BASE}/api/pw/login

Body: {phoneNumber, username}

Sends an OTP to the phone number.

OTP Verify

POST {API_BASE}/api/pw/verify

Body: {otp, phoneNumber, username}

Returns auth token on success.

4 AES-GCM Encryption / Decryption

The proxy encrypts most responses before sending them to the browser

The server returns { "data": "ivHex:ciphertextHex" } — a single string (or array of hex chars that must be joined). The client splits on :, converts both halves from hex, and decrypts with AES-256-GCM.

// Decryption function (module 44269, used everywhere):
const ENC_KEY = "maggikhalo";  // hardcoded in client bundle

async function decrypt(encryptedPayload) {
  // 1. Split "ivHex:ctHex"
  const colonIdx = encryptedPayload.indexOf(":");
  const iv  = hexToBytes(encryptedPayload.slice(0, colonIdx));
  const ct  = hexToBytes(encryptedPayload.slice(colonIdx + 1));

  // 2. Derive 256-bit key (pad/truncate key string to 32 bytes)
  const keyBytes = new Uint8Array(32);
  const enc = new TextEncoder().encode(ENC_KEY);
  for (let i = 0; i < 32; i++) keyBytes[i] = i < enc.length ? enc[i] : 0;

  // 3. Import & decrypt
  const cryptoKey = await crypto.subtle.importKey(
    "raw", keyBytes, { name: "AES-GCM", length: 256 }, false, ["decrypt"]
  );
  const plaintext = await crypto.subtle.decrypt(
    { name: "AES-GCM", iv }, cryptoKey, ct
  );

  // 4. Parse JSON
  return JSON.parse(new TextDecoder().decode(plaintext));
  // ▶ { success: true, data: { ... actual payload ... } }
}

function hexToBytes(hex) {
  const a = new Uint8Array(hex.length / 2);
  for (let i = 0; i < hex.length; i += 2) a[i/2] = parseInt(hex.substr(i, 2), 16);
  return a;
}

5 API 1 — Load All Batches

GET/allbatches.json (same-origin: deltastudy.site/allbatches.json)

Auth: Requires Turnstile session cookie — without it, the server returns the Next.js 404 HTML page instead of JSON.

Cache: The client caches results in localStorage under a key, with a cache-busting ?v=Date.now() on fetch.

The client maps each batch to only {_id, name, previewImage, slug} for the list view, but the full JSON contains all fields below.

Response Format

{ "success": true, "batches": [ { "_id": "698ad3519549b300a5e1cc6a", // MongoDB ID — used as batchId everywhere "name": "Arjuna JEE 2027", "byName": "For IIT-JEE Aspirants", "startDate": "13 Apr 2026", "endDate": "30 Jun 2028", "language": "Hinglish", "previewImage": "https://static.pw.live/.../....jpeg", "feeTotal": 4999, "type": "E_BATCH", // or "REGULAR" "slug": "arjuna-jee-2027-243495", "subBatches": [] // array of sub-batch objects (usually empty) } // ... 8,412 total batches ] }
// Client code (batches page chunk):
let t = await fetch("/allbatches.json");
let a = await t.json();
if (a.success && a.batches) {
  let mapped = a.batches.map(e => ({
    _id: e._id, name: e.name, previewImage: e.previewImage, slug: e.slug
  }));
  setBatches(mapped);
  localStorage.setItem("batchesCache", JSON.stringify(mapped));
}

6 API 2 — Batch Details + Subjects

POST{API_BASE}/api/pw/batchdetailsENCRYPTED

Request body (JSON):

{ "searchParams": { "BatchId": "698ad3519549b300a5e1cc6a" } }

Raw response: { "data": "ivHex:ctHex" } (or data as an array of hex chars to join)

After decryption: { success: true, data: { name, description, shortDescription, subjects[] } }

Fallback: If decryption fails, the client calls api.penpencil.co/v3/batches/{batchId}/details directly (see §11).

Decrypted Response — Subjects Array

{ "success": true, "data": { "name": "Arjuna JEE 2027", "description": "<HTML string with batch features>", "shortDescription": "<HTML string with duration, validity, subjects>", "subjects": [ { "subject": "Physics By Rajwant Singh Sir", // display name "slug": "physics-by-rajwant-singh-sir-964222",// used in URL route "subjectId": "69b5698ee506a608ee297ed1", // used in API calls "_id": "69b5698ee506a608ee297ed1" // same as subjectId }, // ... 12 subjects total (Physics, Chemistry, Maths, Notices, etc.) ] } }
// Client code ([batchId] page chunk):
let e = await fetch(`${API_BASE}/api/pw/batchdetails`, {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({ searchParams: { BatchId: batchId } })
});
let t = await e.json();
if (!t.data) throw Error("No encrypted data");
let s = await decrypt(t.data);   // ▶ { success, data: { subjects, ... } }
if (s.success) setBatchDetails(s.data);

8 API 4 — Topics for a Subject

GET{API_BASE}/api/pw/topics?BatchId={batchId}&SubjectId={subjectSlug}ENCRYPTED

Query params:

REQUIRED BatchId — the batch MongoDB _id

REQUIRED SubjectId — the subject slug (e.g. physics-by-rajwant-singh-sir-964222)

Note: Despite the param name "SubjectId", it takes the subject slug, not the MongoDB ID.

Raw response: { "data": "ivHex:ctHex" }

After decryption: { success: true, data: [ { _id, name, slug }, ... ] }

Decrypted Response

// Client code ([subjectSlug] page chunk):
let url = new URL(`${API_BASE}/api/pw/topics`);
url.searchParams.append("BatchId", batchId);
url.searchParams.append("SubjectId", subjectSlug);  // note: it's the SLUG
let t = await fetch(url.toString());
let a = await t.json();
let s = await decrypt(a.data);

9 API 5 — Content (Videos / Notes / DPP / Tests)

GET{API_BASE}/api/pw/datacontent?batchId=...&subjectSlug=...&topicSlug=...&contentType=...ENCRYPTED

Two calling modes:

Mode A (slug-based): ?batchId={id}&subjectSlug={slug}&topicSlug={topicSlug}&contentType={type}

Mode B (ID-based): ?batchId={id}&subjectId={subjectId}&topicId={topicId}&contentType={type}

contentType values:

videos notes dpp-tests dppVideos dpp-notes lectures

Raw response: { "data": "ivHex:ctHex" }

After decryption: { success: true, data: [ { ...content objects... } ] }

Decrypted Response — Content Object

{ "success": true, "data": [ { "_id": "69ce879a58a0411e9cf01972", "topic": "Bridge Course : Basic Physics Class 9th...", "name": "Bridge Course Lecture", "contentType": "lectures", "status": "COMPLETED", "date": "2026-04-03T00:00:00.000Z", "startTime": "2026-04-03T10:30:00.000Z", "url": "", // video stream URL "pdf_url": "https://...", // for notes/PDF content "video_id": "...", // Vimeo/YT video ID "needs_fetching": true, // if true, fetch via attachment-link "original_schedule_id": "...", // used in attachment-link call "isFree": false, "isDPPNotes": false, "isDPPVideos": false, "isVideoLecture": true, "hasAttachment": false // ... many more schedule fields } ] }
// Client code ([topicSlug] page chunk) — fetches all content types in parallel:
const contentTypes = ["videos", "notes", "dpp-tests"];

for (const ct of contentTypes) {
  // Try ID-based first, fall back to slug-based:
  let url = `${API_BASE}/api/pw/datacontent?batchId=${batchId}&subjectId=${subjectId}&topicId=${topicId}&contentType=${ct}`;
  let r = await fetch(url);
  let j = await r.json();
  if (!j.data) {
    // Fallback: slug-based
    url = `${API_BASE}/api/pw/datacontent?batchId=${batchId}&subjectSlug=${subjectSlug}&topicSlug=${encodeURIComponent(topicSlug)}&contentType=${ct}`;
    r = await fetch(url); j = await r.json();
  }
  let dec = await decrypt(j.data);
  if (dec.success) setContent(ct, dec.data);
}

10 API 6 — Attachments, View & Download

Attachments URL

GET {API_BASE}/api/pw/attachments-url?BatchId={bid}&SubjectId={sid}&ContentId={cid}

Returns { success, data: [url, ...] }. Opens first URL in new tab. Used when hasAttachment=true on a live class.

Attachment Link

GET {API_BASE}/api/pw/attachment-link?batchId={bid}&subjectId={sid}&scheduleId={orig_schedule_id}

Returns decrypted { data: { url, ... } }. Used for PDFs that need fetching (needs_fetching=true).

View (in browser)

GET {API_BASE}/api/pw/view?url={encodedUrl}&filename={name}

Opens a file/PDF inline in a new browser tab. window.open() redirect.

Download

GET {API_BASE}/api/pw/download?url={encodedUrl}&filename={name}

Triggers a file download (window.location.href redirect). Used for PDFs and notes.

11 Direct PW API Fallback (api.penpencil.co)

When the encrypted proxy fails, the client falls back to the real Physics Wallah API directly

Both the [batchId] and [topicSlug] page chunks call this as a fallback/primary source for batch details.

GEThttps://api.penpencil.co/v3/batches/{batchId}/details

Headers:

accept: "*/*"
accept-encoding: "gzip, deflate, br"
accept-language: "en-US,en;q=0.9"
client-id: "5eb393ee95fab7468a79d189"

Response: Plaintext JSON — the real PW batch details object (same structure as the decrypted proxy response, but unencrypted and with more fields like tags, batchAnnouncement, etc.)

Full Loading Sequence (step by step)

1. User visits /study-v2/batches ➞ browser fetches /allbatches.json (needs Turnstile cookie) ➞ renders 8,412 batch cards.

2. User clicks a batch ➞ navigates to /study-v2/batches/{batchId} ➞ calls POST /api/pw/batchdetails (encrypted) + POST /api/pw/live (plaintext) ➞ decrypts batch details ➞ renders subjects list + today's live classes.

3. User clicks a subject ➞ navigates to /study-v2/batches/{batchId}/{subjectSlug} ➞ calls GET /api/pw/topics?BatchId=&SubjectId={slug} (encrypted) ➞ decrypts ➞ renders topic list.

4. User clicks a topic ➞ navigates to /study-v2/batches/{batchId}/{subjectSlug}/{topicSlug} ➞ calls GET /api/pw/datacontent?...&contentType=videos, =notes, =dpp-tests (all encrypted, in parallel) ➞ decrypts each ➞ renders videos/notes/DPP tabs.

5. User clicks a video/PDF ➞ calls /api/pw/attachment-link or /api/pw/attachments-url ➞ opens via /api/pw/view or downloads via /api/pw/download.
